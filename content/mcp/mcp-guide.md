# MCP 入门指南：让 Agent 连接外部工具

## 一句话解释

MCP（Model Context Protocol，模型上下文协议）是一套让 AI 用统一方式连接外部工具和数据源的标准。有了 MCP，AI 不再只能"聊天"，而是可以真正读取你的文件、查询数据库、操作企业系统——就像一个通用插口，插上什么就能用什么。

## 适合谁

* 想知道为什么"别人家的 AI 能读数据库、我的不能"的人。
* 已经会用 Cursor、Codex、Claude Code 等工具，想让 Agent 能力更强的进阶用户。
* 需要让 AI 接入公司内部系统（文档库、数据库、业务平台）的技术负责人。

---

## Part 1：为什么会有 MCP

### 没有 MCP 的世界

AI 工具要连接外部系统，以前的做法是"一个工具一套接口"：

* 让 AI 读本地文件，要单独写一套代码。
* 让 AI 查数据库，要单独写一套代码。
* 让 AI 调用公司系统，又要单独写一套代码。

每接入一个新系统，都要重新开发、重新适配。工具越多，重复劳动越多。

### 有了 MCP 的世界

MCP 把这套"连接"标准化了。任何支持 MCP 的 AI 工具，都能通过同一套协议连接任何支持 MCP 的数据源或工具。

> **一句话类比**：MCP 就像 USB 接口。以前每种设备都有自己的插头，现在大家统一成 USB，插上就能用。

---

## Part 2：MCP 的核心概念

| 概念 | 通俗理解 |
|---|---|
| **MCP Host** | 使用 MCP 的 AI 应用，例如 Claude Desktop、Codex、Cursor |
| **MCP Client** | Host 内部负责和 MCP Server 通信的组件 |
| **MCP Server** | 提供具体能力的服务，例如"文件系统 Server""数据库 Server" |
| **Tools** | Server 提供的可执行操作，例如"读取文件""执行查询" |
| **Resources** | Server 提供的可读取数据，例如文档内容、数据库记录 |
| **Prompts** | Server 提供的预设提示词模板 |

一次典型流程：

```
你问 AI 一个问题
  → AI（Host）判断需要查数据库
  → 通过 MCP Client 调用 MCP Server
  → Server 执行查询并返回结果
  → AI 根据结果组织答案
```

## Part 3：MCP 能帮你做什么

| 能力 | 通俗理解 | 示例 |
|---|---|---|
| 读写本地文件 | 让 AI 直接操作你的文件 | "把这份 Excel 里的数据整理成表格" |
| 查询数据库 | 让 AI 直接查业务数据 | "查一下上个月各区域的销售数据" |
| 连接企业系统 | 让 AI 操作内部平台 | "在审批系统里发起一个流程" |
| 调用外部 API | 让 AI 使用第三方服务 | "查一下今天的天气并安排户外会议" |
| 访问知识库 | 让 AI 基于内部资料回答 | "根据公司合规手册回答这个问题" |

---

## Part 4：怎么开始用 MCP

不同 AI 工具配置 MCP 的方式不完全一样，但思路是一致的：

1. **确认你的工具支持 MCP**：目前 Claude Desktop、Codex、Cursor 等主流 Agent 工具都支持。
2. **找到一个 MCP Server**：可以是官方提供的，也可以是社区开源的，例如文件系统、GitHub、数据库等。
3. **在工具里配置 MCP Server**：通常是在配置文件里填入 Server 的启动命令或地址。
4. **授权和验证**：确认 AI 能成功连接到 Server，并能调用它的能力。
5. **开始使用**：直接在对话里提需求，AI 会自己决定何时调用 MCP。

> 具体配置步骤以你使用的工具和 Server 的官方文档为准。不同版本的界面和配置方式可能不同。

## Part 5：医药场景怎么用

| 场景 | MCP 能做什么 |
|---|---|
| 文献整理 | 连接文献数据库，让 AI 直接检索并整理证据 |
| 合规查询 | 连接公司制度文档库，让 AI 基于最新版本回答 |
| 数据分析 | 连接内部数据平台，让 AI 直接查询和汇总 |
| 内容生产 | 连接素材库，让 AI 读取模板和参考材料 |
| 流程自动化 | 连接审批、报销等系统，减少重复操作 |

## Part 6：安全与合规（重要）

MCP 让 AI 获得了"动手"的能力，同时也放大了风险。以下几条必须注意：

* **只连接可信来源的 MCP Server**：第三方 Server 可能读取或修改你的数据。
* **最小权限原则**：只授予必要的权限，不要给 AI 整个磁盘或全部数据库的访问权。
* **敏感数据脱敏**：不要把未脱敏的患者信息、客户信息直接交给 AI 处理。
* **确认数据流向**：了解数据是留在本地，还是会发送到外部服务。
* **保留人工复核**：AI 执行的写操作（改文件、发邮件、提交表单）应先确认再执行。

> 详细的数据安全与合规要求，见 `content/security/data-security-and-compliance.md`。

```text
我想给当前的 AI 工具配置一个 MCP Server。
请先不要直接操作，先帮我梳理：
1. 我当前使用的工具支持哪些类型的 MCP Server
2. 我的需求最适合用哪一类 Server
3. 配置需要哪些前置条件
4. 这个 Server 需要什么权限，有哪些安全风险
5. 配置完成后如何验证是否成功
```

## 学完后下一步

1. 确认你常用的 AI 工具是否支持 MCP。
2. 从最简单的 MCP Server（如文件系统）开始尝试。
3. 配置成功后，用一个真实的小任务验证效果。
4. 逐步学习如何连接数据库和企业系统。
5. 每次新增 MCP 权限前，先评估安全风险。

如果你能完成这些，就已经从"使用 AI 对话"进阶到"让 AI 连接真实工作系统"的阶段了。
