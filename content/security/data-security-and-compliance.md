# AI 使用中的数据安全与合规指南

## 一句话解释

这份指南帮你判断：什么数据可以交给 AI、可以交给哪个 AI、怎么交才安全。它不是让你"因为怕风险就不用 AI"，而是让你知道边界在哪里，从而放心地用 AI 提效。

## 适合谁

* 在工作中使用 AI 处理业务数据的医药行业从业者。
* 需要把 AI 引入团队流程、但担心合规风险的管理者。
* 想弄清"公网 AI""本地部署""企业内网 AI"有什么区别的人。

---

## Part 1：先分清三类 AI 环境

不同环境下，数据流向完全不同，风险也不同。

| 类型 | 数据流向 | 风险等级 | 典型例子 |
|---|---|---|---|
| **公网 AI 工具** | 数据发送到厂商服务器，可能被用于训练 | 高 | 网页版 ChatGPT、Gemini、DeepSeek |
| **企业内网 AI** | 数据留在企业网络内，通常不用于训练 | 中 | 企业自建的知识库助手、Workbuddy |
| **本地部署 AI** | 数据完全留在本机，不联网 | 低 | 本地运行的模型（如 Ollama） |

> **核心原则**：数据越敏感，越应该交给内网或本地环境处理。

---

## Part 2：数据分级——什么能交，什么不能交

### 四级分类

| 等级 | 数据示例 | 处理建议 |
|---|---|---|
| **公开信息** | 已发布指南、公开论文、官网内容 | 可交给公网 AI |
| **内部信息** | 内部流程文档、培训材料 | 建议脱敏后使用，优先内网 AI |
| **敏感信息** | 未公开商业策略、未发表数据 | 仅限内网或本地 AI，需审批 |
| **高度敏感信息** | 患者信息、临床试验双盲数据、个人身份信息 | 禁止交给公网 AI，严格按合规流程处理 |

### 绝对不要交给公网 AI 的内容

* 患者姓名、身份证号、电话、住址、病历原文。
* 未发表的临床试验数据、双盲数据。
* 公司未公开的商业战略、财务数据、并购计划。
* API Key、密码、Token 等凭证。
* 包含客户（医生）个人信息的报销凭证。

---

## Part 3：脱敏——把敏感数据变成可用数据

很多时候你不需要原始数据，只需要"结构"。脱敏就是去掉可识别的部分，保留有用的部分。

| 原始数据 | 脱敏后 |
|---|---|
| 张医生，北京协和医院，138****1234 | 医生A，北方三甲医院 |
| 患者李某某，65岁，2型糖尿病 | 患者A，65岁，2型糖尿病 |
| 某药品Q3销售额 1.2 亿元 | 某药品Q3销售额 1.2 亿元（如属内部数据，仍需内网处理） |

> **重要**：脱敏要彻底。只改名字但保留其他可组合识别的信息，仍然可能被重新识别。

## Part 4：API Key 与账号安全

### API Key 的正确用法

* 使用 `.env` 环境变量文件保存，不要写进代码。
* 确认 `.env` 已被 `.gitignore` 忽略。
* 上传到 GitHub 前检查是否包含密钥。
* 不同的项目使用不同的 Key，便于追责和吊销。
* 怀疑泄露时，立即到平台删除并重新创建。

### 常见泄露场景

| 场景 | 后果 |
|---|---|
| 把 Key 写进代码并上传 GitHub | 机器人会秒级扫描并盗用 |
| 把 Key 粘贴到对话里 | 对话记录可能被留存 |
| 把 Key 放在截图里 | 截图可能被转发 |
| 把 Key 存在共享文档 | 有权限的人都能看到 |

## Part 5：合规出境

很多医药企业属于外企或有跨境业务，数据出境是重点合规议题。

* **了解公司政策**：使用公网 AI 前，先确认公司是否有数据出境限制。
* **确认服务器位置**：有些工具的国际版和国内版数据存储地不同。
* **保留使用记录**：重要场景下的 AI 使用应可追溯。
* **遇到不确定的情况，先问合规部门**：AI 的回答不能替代合规判断。

---

## Part 6：AI 输出的合规检查

AI 生成的内容同样需要审核。

* **医学内容**：必须有权威来源，不能直接把 AI 生成的数据对外使用。
* **对外材料**：必须走公司既有的 Medical / Legal 审核流程。
* **引用信息**：AI 可能编造参考文献，使用前必须核对原文。
* **免责声明**：涉及健康科普的内容应包含合规声明。

> **一条底线**：AI 是提效工具，不是责任主体。最终内容由人负责。

---

## Part 7：快速自查清单

在把数据交给 AI 前，问自己这几个问题：

- [ ] 这些数据是公开、内部、敏感还是高度敏感？
- [ ] 我用的 AI 是公网、内网还是本地？
- [ ] 数据是否已经脱敏？会不会被重新识别？
- [ ] 有没有把 API Key 或密码暴露在对话里？
- [ ] 公司的合规政策是否允许这样做？
- [ ] AI 的输出我会人工复核吗？

如果有一项不确定，先停下来确认，而不是先做了再说。

## 推荐 Prompt

```text
我准备把下面这批数据交给 AI 处理，请你先帮我做一次合规风险检查：
1. 这些数据属于哪个敏感等级
2. 是否有可识别个人信息
3. 哪些字段需要脱敏
4. 适合用公网 AI、内网 AI 还是本地 AI
5. 处理过程中还有哪些风险点

数据说明：[描述数据结构，不要直接粘贴真实敏感数据]
```

## 学完后下一步

1. 对照数据分级表，梳理你日常工作中会接触的数据类型。
2. 检查自己正在使用的 AI 工具属于哪一类环境。
3. 检查项目里是否存在硬编码的 API Key。
4. 和团队确认 AI 使用的合规边界。
5. 把这份指南的快速自查清单放进你的日常工作流程。
