# Skill 理论知识：从 Prompt 到 Skill

## 一句话解释

Skill 是把个人优秀的工作方法，变成 AI 可以反复调用的能力。Prompt 解决一次任务，Skill 沉淀一套方法。

## 适合谁

* 用 Prompt 能让 AI 输出内容，但在高频、复杂、有规则的业务任务里总是"不稳定"的人。
* 想理解 Skill 到底是什么、和 Prompt/Agent 什么关系的人。
* 想判断自己的工作是否适合做成 Skill 的人。

---

## Part 1：Agent 分类——两个流派

在理解 Skill 之前，先看清楚当前 AI Agent 的两大流派。

### 厂家原生 Agent

大模型厂家把自己的模型、Agent harness（执行体系）、执行环境和产品入口打包成一体。不只是回答你怎么写代码，而是可以读文件、改内容、运行检查、生成结果。

* **OpenAI - Codex**
* **Anthropic - Claude Code**
* **Google - Antigravity**

核心：原厂模型 + 原厂执行体系。模型与 Agent harness 深度整合，任务执行闭环强。

### 多模型 Agent Shell

第三方产品把多个模型、用户工作台、上下文管理和工具编排整合在一个操作界面里。价值是把不同模型放进一个用户真正工作的地方，更方便地调度 AI。

* **Anysphere - Cursor**（调用 /best-of-n 多模型编排）
* **Tencent - WorkBuddy**
* **ByteDance - Trae**

核心：工作台 + 多模型编排。模型选择灵活，协同体验强。

### 核心概念

| 概念 | 理解方式 |
|---|---|
| **执行体系（Harness）** | AI 拿到任务后如何从目标走到结果：任务理解 → 拆解 → 上下文理解 → 工具调用 → 执行环境 → 错误恢复 → 结果验证 → 产物交付 |
| **工作台** | 用户和 AI 在同一个界面中一起合作，如 IDE 里的代码直接修改、tab 补全 |

厂家原生 Agent 的核心是模型和执行体系，多模型 Agent Shell 的核心是工作台和多模型编排。

## Part 2：为什么需要 Skill

### 普通 Prompt 的问题

一个 Prompt 能输出内容，但在高频、复杂、有规则的业务任务里，最大问题是"不稳定"。

**示例：会议纪要**

> "请帮我整理一份会议纪要。"

看起来没错，但它通常只是在总结内容，不一定能识别类型、形成行动闭环，也不一定能守住业务边界。

真正可用的纪要需要回答：

1. **会议类型**：这到底是项目会、复盘会、客户会，还是跨部门对齐会？
2. **行动闭环**：谁负责下一步？什么时候完成？依赖什么条件？
3. **事实边界**：哪些已确认，哪些只是客户兴趣或待确认信息？
4. **质量检查**：未审核材料、医学边界、竞品口头信息是否被正确标注？

> 普通 Prompt 让 AI "写出来"；Skill 让 AI 按标准稳定交付。

## Part 3：Skill 到底是什么

### 官方定义

> "A modular package that extends an AI agent with reusable instructions and domain expertise."
> — Anthropic Claude Docs, Agent Skills overview

### 业务语言翻译

Skill 重点是两个词：**Reusable**（可复用）和 **Domain Expertise**（领域经验）。

* Reusable：把同一套做法沉淀下来，以后遇到类似任务可以反复调用。
* Domain Expertise：把业务经验、判断规则、模板和风险边界交给 Agent。

### 三者关系

| AI 概念 | 企业管理类比 | 会议纪要场景 |
|---|---|---|
| **Prompt** | 口头交代的临时任务 | "帮我整理这次会议纪要" |
| **Agent** | 负责执行任务的人 | 读取记录、理解内容、生成结果的 AI 助手 |
| **Skill** | 团队的标准作业指导书 SOP | 会议纪要与行动闭环标准处理流程 |

> Agent 决定谁来干活；Prompt 决定这次干什么；Skill 决定按什么标准干。

**Skill = 可复用的指令 + 领域经验 + 固定工作流**

## Part 4：会议纪要 Skill 的工作流

以会议纪要 Skill 为例，一个 Skill 通常是一条清晰的树状工作流：

1. **投入会议记录**：会议转写、聊天记录、录音整理稿、会后补充反馈，统一作为完整输入
2. **判断会议类型**：不是直接总结，而是先判断"这是什么会"，会议类型决定纪要重点和输出模板

| 会议类型 | 纪要重点 | 不应该只写什么 |
|---|---|---|
| 项目推进会 | 进度、阻塞点、下一步、责任人、截止时间 | 不只是"讨论了项目进展" |
| 决策会 | 决策事项、备选方案、决策理由、影响范围 | 不只是"大家进行了讨论" |
| 复盘会 | 目标 vs 结果、成功经验、问题原因、改进动作 | 不只是"活动圆满结束" |
| 客户会议 | 客户关注点、明确需求、异议、机会、后续跟进 | 不只是"客户反馈积极" |
| 周会 | 本周完成、下周计划、需要协同的问题 | 不需要写成长篇正式纪要 |
| 跨部门对齐会 | 共识、分歧、依赖关系、需要升级的问题 | 不只是罗列各方发言 |

3. **选择纪要结构**：调用模板（结论、行动项、风险、待确认、上级摘要）
4. **提取关键信息**：抽取客户信号、行动项、责任人、截止时间与依赖条件
5. **质量检查**：检查已确认/待确认、责任人、截止时间、合规与医学边界
6. **交付结果**：输出完整纪要、行动项表、风险边界和上级摘要

复杂 Skill 可在每一步加入搜索、知识库、模板、脚本、中间产物或外部工具调用。

## Part 5：哪些工作适合变成 Skill

满足 4 条以上，就是非常好的 Skill 候选场景：

1. **频次高**：每周、每月都会反复处理，而不是一次性问题
2. **流程定**：每次处理的思考步骤和逻辑大体相似
3. **格式死**：最终需要输出标准业务交付物，如纪要、表格、报告、代码
4. **规则多**：经常需要提醒 AI 注意公司规则、禁忌或边界
5. **价值大**：一旦沉淀出来，值得团队新人直接套用
6. **有标杆**：手头有明确的好模板、好样例或优秀输出可以学习

> 当你第三次教 AI 做同一件事，就该考虑把它变成 Skill。

## Part 6：好 Skill 的六大要素

从一个真实的 frontend-slides Skill 拆解中，可以抽象出好 Skill 必须包含的六个要素：

### 1. 触发条件 Trigger
什么时候应该调用？Skill 的"门牌"：让 Agent 知道什么任务该找它，而不是所有任务都硬用。

### 2. 角色定位 Role
AI 此刻应该扮演谁？AI 的"岗位说明书"：不是普通聊天助手，而是某类任务专家。

### 3. 工作流程 Workflow
先做什么，后做什么？Skill 的"SOP"：把优秀经验拆成稳定步骤，减少每次重新教 AI。

### 4. 参考资源 Resources
AI 可以参考什么？AI 的"工具箱"：模板、风格库、示例、组件、脚本或知识资料。

### 5. 输出格式 Output
最后交付什么？AI 的"交付物标准"：避免输出散、乱、泛，保证结果可直接使用。

### 6. 质量检查 QA / Guardrails
如何避免翻车？AI 的"验收清单和安全边界"：防止遗漏、编造、溢出或不符合标准。

### frontend-slides 案例对应

| 要素 | frontend-slides 中的体现 |
|---|---|
| Trigger | 从头开始或通过转换 PPT 生成 html 幻灯时 |
| Role | 前端演示设计与生成助手 |
| Workflow | 问用途/密度 → 3个预览 → 完整 deck |
| Resources | 风格预设、HTML模板、CSS、动效/导出脚本 |
| Output | 单文件 HTML；可转网页 / 导出 PDF |
| QA | 16:9 舞台、无溢出、适合投影 |

> 好 Skill = 方法沉淀 + 交付标准 + 质量边界。不是写一段更长 Prompt，而是构建一套可触发、可执行、可复用、可交付、可检查的 AI 工作系统。

## 推荐 Prompt

```text
请你作为"会议纪要 Skill"来处理我提供的会议记录。
你的任务不是简单总结会议内容，而是按照固定工作流，
把会议内容整理成一份可以推动后续行动的专业会议纪要。

请按照以下流程执行：
1. 投入会议记录并识别基础信息
2. 判断会议类型
3. 选择纪要结构
4. 提取关键信息（核心结论、已确认/待确认事项、客户信号、行动项）
5. 质量检查
6. 交付完整纪要 + 行动项表 + 风险清单 + 上级3条摘要
```
