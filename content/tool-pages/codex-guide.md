# OpenAI Codex 新手学习页

## 一句话解释

OpenAI Codex 是 OpenAI 官方推出的 AI 编码 Agent。它既能像 Cursor 一样在编辑器里帮你读代码、改代码，也能在终端命令行里自主执行任务（修报错、跑测试、查项目结构），还可以把任务交给云端异步处理——你在一条对话里说目标，它自己去拆解、执行和验证，最后把结果交给你确认。

---

## 适合谁

- 想用 AI 完成项目级任务，而不只是写代码片段的人。
- 喜欢"说目标、看结果"的工作方式，不想逐行盯着 AI 改代码的人。
- 需要把重复性开发任务（跑测试、修 lint、重构、写文档）交给 Agent 自动处理的人。
- 想体验 OpenAI 最新编码模型能力的人。

## 不适合谁

- 纯代码小白、不想接触任何文件和项目结构的人——建议优先学习 [Cursor](./cursor-beginner-guide.md) 或 [Trae](./trae-guide.md)。
- 希望 AI 一次性自动做完所有事情、自己完全不检查结果的人——任何 Agent 工具都不建议这样做。

---

## 当前形态（截至 2026 年）

Codex 从 2025 年大规模重推后经历了多次迭代，目前已经不只是"一个模型"或"一个 API"，而是一套完整的 Agent 编码产品线：

| 形态 | 怎么用 | 适合场景 |
|---|---|---|
| **Codex（桌面/IDE 插件）** | 在编辑器里和 AI 对话，它可以直接读取和修改项目文件 | 日常编码、项目修改、调试报错 |
| **Codex（终端 CLI）** | 在命令行里启动，AI 可以执行命令、运行测试、跨文件修改 | 自动化运维、批量修复、项目诊断 |
| **Codex（云端 Agent）** | 在网页端发起任务，AI 在云端沙箱环境中异步执行，完成后通知你 | 耗时任务、多步骤重构、并行任务 |
| **OpenAI API（编码模型调用）** | 通过 API 接口调用底层编码模型，嵌入自己的脚本或产品 | 批量自动化、企业集成 |

> Codex 的底层使用 OpenAI 最新的编码优化模型。具体模型名和版本号迭代很快，第一次使用时以 OpenAI 官方页面显示的当前可用模型为准。

## 它能帮你做什么

| 能力 | 新手理解 | 示例任务 |
|---|---|---|
| 解释项目结构 | 让 AI 告诉你每个目录做什么 | "这个项目的入口在哪里？" |
| 跨文件修改 | 一个指令同时改多个文件 | "把所有组件的按钮文案从英文改成中文" |
| 自主修报错 | 运行命令、看报错、自己修、再跑 | "跑一下测试，有报错就帮我修好" |
| 代码生成 | 从需求直接生成页面或函数 | "帮我做一个数据展示卡片组件" |
| 写文档 | 生成 README、注释、API 说明 | "给这个项目写一段安装说明" |
| 云端异步任务 | 把耗时任务交给云端，你继续做别的事 | "重构这个模块的错误处理逻辑" |

## 使用前准备

| 准备项 | 是否必须 | 说明 |
|---|---|---|
| OpenAI 账号 | 是 | 需要有 OpenAI 账号（免费或付费均可，但能力有差异） |
| 一个项目文件夹 | 建议 | Codex 需要读取项目文件才能干活 |
| Node.js 环境 | 视形态而定 | 终端 CLI 需要安装 Node.js；桌面 IDE 版不需要 |
| Git 版本控制 | 强烈建议 | AI 会直接修改文件，没有 Git 就无法安全回退 |
| 海外网络环境 | 视情况而定 | 国内直连可能不稳定，具体以实际网络条件为准 |

## 第一次使用流程

### 方式 A：在编辑器/IDE 中使用

1. 按官方指引安装 Codex 插件或桌面应用。
2. 打开你的项目文件夹。
3. 在对话区直接下达指令，例如：

```text
请你先阅读当前项目结构，然后用新手能理解的语言解释：
1. 这个项目是做什么的
2. 主要目录分别有什么作用
3. 我应该从哪个文件开始看
4. 如果我要修改首页，应该看哪些文件
```

4. AI 会自行扫描文件并给出回答。如果要修改代码，它会先告诉你准备改哪里，你确认后再执行。

### 方式 B：在终端命令行中使用

1. 安装 Codex CLI（具体命令以官方文档为准）。
2. 进入项目目录，启动 Codex。
3. 直接下达指令：

```text
请帮我运行项目里的测试脚本，如果有报错就分析原因并修复，
修完之后重新跑一次，确保全部通过再告诉我。
```

4. AI 会自己执行命令、查看输出、修改文件、再次运行——整个闭环你只需要等结果和最后确认。

### 方式 C：使用云端 Agent

1. 在网页端发起一个任务，描述你的目标。
2. Codex 会在云端环境中自主执行（读取代码、修改文件、运行测试）。
3. 完成后你会收到通知，可以查看它做了什么改动，选择接受或拒绝。

> 云端任务的好处是你不需要在本地配环境，适合处理较大的重构或耗时任务。

## 推荐新手任务

### 任务 1：让 Codex 解释项目结构

目标：知道项目大概由哪些部分组成。

```text
请用新手能理解的语言解释当前项目结构，并告诉我如果只想修改首页，应该先看哪些文件。
```

完成标准：AI 能指出 2-5 个关键目录或文件，并说明每个文件的用途。

### 任务 2：让 Codex 修复一个报错

目标：体验 Agent 的"自动排错"能力。

```text
请运行项目，如果有报错，先分析原因，再帮我修复。
修复后重新运行，确认没问题了再告诉我。
```

完成标准：项目能正常运行，没有新增报错。

### 任务 3：让 Codex 写一段文档

目标：让 AI 理解代码并生成说明文字。

```text
请阅读这个项目的核心逻辑，帮我在 README 里补一段"如何运行"的说明。
先告诉我你准备写什么，等我确认后再写入文件。
```

完成标准：README 中新增了清晰可用的运行说明。

## 常见错误与防护

| 问题 | 可能原因 | 解决方法 |
|---|---|---|
| AI 改了很多文件 | 任务范围太大，或没有要求先说明计划 | 使用"先告诉我要改哪些文件，等我确认后再改" |
| 修改后项目跑不起来 | AI 的修改有副作用，或依赖版本不匹配 | 先用 `git reset --hard HEAD` 回退，再把完整报错交给 AI 分析 |
| AI 说我没有权限 | 目录权限或安全策略阻止了文件操作 | 检查文件夹读写权限，或在受信任的目录中操作 |
| 响应很慢 | 任务本身复杂，或网络不稳定 | 简单任务用 IDE 模式，大任务可考虑云端异步模式 |

## 和同类工具的区别

* **vs. ChatGPT 网页版**：ChatGPT 适合聊天、润色文章、发散思考；而 **Codex** 拥有读写本地文件、运行命令和自主修错的真实开发能力。
* **vs. Cursor 编程工具**：Cursor 更偏向"你在编辑器里一边看代码一边和 AI 协作"；Codex 更偏向"你给目标，它自己去干"，尤其是终端和云端模式可以做到更强的自主性。
* **vs. Claude Code**：两者都是终端+IDE 双形态的 Agent。Claude Code 背靠 Anthropic 模型，Codex 背靠 OpenAI 模型，工作流和交互方式各有特色，具体选择看团队习惯和模型偏好。

## 学完后下一步

1. 从 GitHub 下载一个简单项目，用 Codex 打开。
2. 让 Codex 解释项目结构。
3. 给 Codex 一个小修改任务，体验"先说明再修改"的工作流。
4. 如果碰到报错，把完整报错交给 Codex，体验自动排错。
5. 学习用 Git 保存修改，确保出错时可以安全回退。

如果你能完成这些任务，就已经从"只会问 AI 问题"进入到"能用 AI Agent 处理一个项目"的阶段了。
